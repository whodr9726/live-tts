# 语音陪伴模式

默认情况下，agent 只在用户要求时才朗读。这个文档说明怎样把它变成
**每轮回复都先用语音说出来**的陪伴模式（口语陪练、语音助手、有声编程助手都适用）。

## 1. 项目规则

把下面这段放进项目的 `AGENTS.md`（或 CLAUDE.md / 系统提示词），agent 每轮都会照做：

```markdown
## 语音规则（每轮默认）

1. 先想好要说的内容（口语化、短句、1~3 句）。
2. 把只包含要朗读的正文写入 `.cache/tts/reply.txt`（UTF-8）。
3. 后台朗读：`python .agents/skills/live-tts/say.py --file .cache/tts/reply.txt --detach`
4. 再在界面输出文字回复。

例外：纯技术任务（改代码、查文件、装环境、看日志）默认不朗读；
用户说"安静 / 别读了"→ `say.py --stop`，直到用户说继续。
```

更短的版本（命令式宿主）：

```markdown
你的每条面向用户的回复都要先朗读再打字：
`python <skill>/say.py --text "<要念的正文>" --detach`
代码块、表格、路径、日志不朗读。
```

## 2. 英语口语陪练示例

角色提示词（可直接用来开启一个 Ryan 陪练会话）：

```text
你是 Ryan，一位母语是英语的口语陪练。
用户说英语（或中文求助），你用英语回答，并把回答用语音读出来。

每轮：
1. 1~3 句口语化英文，结尾留一个自然的问题。
2. 用 say.py 朗读（只放英文，中文解释不放进朗读文件）。
3. 再输出文字。

纠错只纠最影响理解的一处：Actually, you might say "...".
用户说"太快 / 慢一点 / 听不清" → --rate 0.85；说"太慢" → --rate 1.1。
用户说"安静 / 别读了" → say.py --stop，之后不再朗读。
```

启动命令：

```bash
python say.py --status
python say.py --text "Hey, I'm Ryan. Good to finally talk with you. What did you do today?" --detach
```

## 3. 设计建议

- **先朗读再打字**：朗读是异步的，先启动它，用户读文字时声音已经在播。
- **朗读文件只放正文**：`say.py` 会清洗 Markdown，但纯文本效果最自然。
- **一句一轮**：太长会被切段并串行播放，打断体验变差。
- **不要每轮都念"好的""明白了"**：把口头禅留给真正需要互动的场景。
- **技术任务保持安静**：命令输出、错误堆栈念出来既难听也没用。
- **语音不是唯一通道**：重要信息（路径、数字、代码）仍然要打字。

## 4. 与其他模式共存

- 语音开关是"用户意图"级别的：用户说停就停，说继续就继续。
- 同一时间只有一条朗读：新朗读会自动杀掉上一条 worker 进程。
- 需要生成音频文件而不是播放时：`--no-play --out some.wav`。
